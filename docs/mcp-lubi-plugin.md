当前发布基线 **1.7.1**，1.8.0 是本地开发版（未发布），最低 Obsidian 版本在 manifest 中声明为 **1.13.7**。源码在 `插件源码/lubi/`，随 Vault 分发的安装文件在 `.obsidian/plugins/lubi/`。使用方法以根目录 README 与教学手册为准，版本变更以 CHANGELOG 为准。

## 数据约定

- 日记只更新 `## 记录`，其他章节和手写非记录行保留。
- 实际分钟为 `[时长:: …]`；任务预计快照为 `[预计用时:: …]`，不参与实际总时长统计。历史无快照记录不取当前任务预计补算。
- `[待确认:: 按计划]` 不等于测得的实际用时；拖动、确认或表单保存后核对。`[待确认:: 实际开始未核对]` 则说明用时已填写、时间位置尚待核对，时长对比可用但覆盖位置不能冒充已核实。
- 地点是任务上的可选 `location` 字符串，任务表单位于重复设置下方；JSON 导入和 AI 草稿均支持，省略表示空地点，不从其他任务继承。地点不写入实际记录，不影响时长统计。
- 任务 JSON 仍为 `{ "version": 14, "tasks": [] }`；清空任务不删除日记。操作前备份到仓库外。
- 名称候选从同分类全部历史时间记录和现存任务汇总；本地设置中的 `nameUses` 仅记录分类、名称与最近使用时间，不写入任务 schema 或日记。成功新建或改名 / 改分类后更新；取消或仅编辑其他字段不更新；缓存元数据不复活已删除的来源名称。
- 计划日历日 / 周固定显示 0–24 点；兼容保存的旧时段字段不再裁切网格，任务字段结构不变。

## 默认界面

- MONO 默认列表·日：主栏依次为跨日期「需我处理」和复用原 `renderLists` 的选中日分组任务（保留父级编辑、手动排序、拖放及快速添加）；侧栏依次为后台任务、本人用时、未安排，后台任务不重复出现。其他八种展示／范围组合仍可进入。
- `src/ui/monochrome.ts` 提供局部共用任务概览与本人用时卡；Tokens 限于 `.lubi-root`、`.lubi-modal`、`.lubi-settings`，明暗均为无彩色，不修改外层 Obsidian 强调色或用户分类配置。
- `actualRequired` 关联记录以任务只读上下文及用时优先，计划字段使用默认关闭的原生 details；独立记录以名称优先、完成选项隐藏。独立时间沿用原 record-origin 关联格式、estimate=0，不生成规划预测或待办。完成 checkbox 是显式意图，不是 Save 的默认副作用；已完成的禁用 checkbox 不能把并发重开的任务再完成。
- 实际日期与 completionDate 独立；日期切换先清空旧用时，再仅读目标日。每次请求带 generation，过期或窗口已关闭的响应忽略；读取期间用时／时间及必要 Save 禁用，错误时不猜测空记录。多段只读时仍可选日期，保存期间锁住日期。

- 统一任务表单先显示计划日期 / 时间、预计、重复，再显示实际日期 / 时间、实际用时；实际字段容器为普通 div，不再使用折叠标题。回顾页隐藏顶栏新建按钮，计划页保留，快捷键入口不变。日历日的规划拖选背景混合主题实色，选区内遮住当前时间红线，不隐藏选区外红线及左侧标签。

- 顶部仅计划 / 回顾两页，数字快捷键 1 / 2；默认今天的列表·日，可切换日期。原 `open-today` 命令 ID 保留并转入今天的日历·日，回顾日期点击也进入对应日视图，无独立每日渲染路径。

- 规划与时间记录表单共用名称输入下拉，惰性读取全部日记，文件变更和设置保存时失效缓存；支持大小写无关的包含匹配、5 行内部滚动、方向键选择、Enter 填名和 Esc 收起。保持自由输入；支出仍走既有原生联想。设置写入排队，排序元数据写入失败不使已成功保存的内容重复提交。

- 日历日视图以 `data-area` 限定悬停与选区边界；拖选类型取按下时的区域，左侧复用记录表单、右侧复用任务表单并预填排期。仅当定时计划列存在时启用右侧创建，取消不写数据。
- 计划页将本人投入 / 覆盖及条件性重叠 / 待确认摘要移到规划切换栏日期之后，保留时间轴和一个侧栏；分类分布直接显示在侧栏顶部，当天计划在下方独立卡片中显示数量和进度条，原生下拉清单默认展开，复用标准任务行按开始时间列出当天全部任务，未定时任务放在最后；同日刷新保留展开状态；空白时段使用原生 `details` 默认展开，仍可收起。
- 规划日程普通悬停线按鼠标在列内的精确位置绘制，横线笔画中心与时间标签保持对齐；悬停视觉与实际创建 / 拖入 / 移动 / 伸缩的时间网格吸附分离。
- 计划页有日历 / 甘特图 / 列表，每种共用日 / 周 / 月、选中日期与范围导航。`TasksState` 仅保存面板内存中的展示方式、范围、日期及甘特折叠；默认日历·日。`ganttWindow` 与 `stepGanttDate` 统一自然周 / 月和月末钳制；月历补齐周格，其他方式限定自然范围。窄屏显示同一种展示方式，不再独立使用议程。
- `planOccurrences` 复用 `ganttRows` 的日期段，生成明确排期的规划任务及重复发生日；按日期 / 开始排序，普通跨度只产生一个列表条目。日历按每个日期投影，只有明确安排执行日显示其时刻，其他跨度日期放全天区；有自身明确排期的父任务也保留，纯派生父级仅作分组 / 路径，甘特保留层级汇总。`planInbox` 排除显式跨度与记录生成的任务；`planDatePatch` 复用跨度平移保护，月历移动不清空开始时间。
- `dailyGanttRows` 按发生日投影明确排期的规划任务（包含显式父任务），排除直接记录生成的任务；00:00–24:00 时间轴与任务条共享两端留白，未定时不伪造全天、未填预计不补值、跨午夜只裁切视觉。普通任务时间交互复用 `startDrag(axis=x)` 与排期撤销；重复和跨日裁切条不直接拖动。
- `ganttRows` 是 schema v14 的只读投影：排除 `origin=record`，完整起止日期优先于单日安排；父级缺少显式跨度时汇总子任务日期，重复任务复用 `occursOn` 与 `doneDates` / `skipDates`，不回写派生范围。
- 甘特拖动复用 `startDrag` 的水平日期步进，普通单日平移仅改 `date`，拉伸生成已有的 `startDate` / `endDate` 字段；显式跨度平移同步已有 `date`，伸缩不能排除安排日，汇总父任务与重复分段不可拖动。保存复用 `updateScheduleWithUndo`，字段级冲突保护、失败时仍匹配字段的内存回滚及日期一致性撤销保护不修改实际记录。
- 规划页移除独立项目面板、空状态、新建项目按钮及旧的甘特展示；父子任务分组、父任务编辑和项目跨度字段保留，schema v14、进度 / 跨度模型不变。
- `src/ui/calendarDay.ts` 内嵌原每日时间轴完整操作，`src/ui/daySummary.ts` 保留分类分布及计划进度卡；日历·日时间轴在左、摘要卡在右，窄屏仍按时间轴、摘要卡排列；计划日视图异步读取所选日日记，统计日记时间记录而非任务预计值，保留空环、零进度及默认展开的时间排序清单。其他规划展示不读取日记摘要。
- 日历 / 甘特图 / 列表的日 / 周 / 月均使用左侧主内容、右侧任务侧栏，DOM 阅读及键盘顺序一致；右侧宽度统一为日历·日的 300px，900px 及以下面板统一单列，侧栏在主内容下方铺满可用宽度；计划页滚动容器使用稳定滚动条占位，内容长短切换不改变侧栏水平位置；甘特图内部任务名称列不移动。日历 / 甘特图 / 列表均保留选中日与未安排清单；列表主区域继续显示日期范围，右侧上方为选中日操作卡、下方为未安排，复用 renderLists 与相同任务 ID，不新增数据副本；原清单手动排序及排期入口保留。JSON 导入按钮在 AI 创建左侧，使用独立粘贴弹窗和严格共享格式解析；设置的只读提示词与复制按钮复用该格式，不读取密钥或历史任务。通过后以单次队列写入追加新任务，先备份现有任务文件，文件外部变动时拒绝覆盖。AI 创建以普通按钮显示在顶栏「新建任务」左侧，复用原弹窗与选中日期；更多菜单不重复列出，回顾页仍不显示该入口，窄屏保留有读屏名称、无悬停提示的图标按钮。
- 事项排行显示耗时前 5 项，保留次数和耗时，复用分类明细的行、底轨与分类色填充条；按最大事项耗时缩放，不改变聚合口径。
- 回顾指标合并为一组，趋势图常驻，分类 / 事项 / 支出明细及详细分析默认折叠；不改变统计口径。
- 点击计划块或对其按 Enter / Space，打开已有任务的规划编辑，复用铅笔按钮行为；拖动与伸缩不变，实际记录通过任务清单 ▶ 创建。
- 每日记录与计划块共用编辑 / 删除两按钮工具条，不提供复制到明天；计划删除仅取消当天排期，待确认记录通过标签确认。
- 顶部仅一个强调的新建按钮；任务 ▶ 常驻，辅助操作在悬停 / 聚焦时显示，触屏直接可用。样式不使用渐变或玻璃效果。

### 设置页

`src/ui/settingsTab.ts` 按插件更新、数据与日程、分类、AI、支出和维护分区；AI 使用原生折叠，模型输入由 `src/ui/modelPicker.ts` 提供主题化可编辑 combobox，获取或点击展开列出全部模型，只有 input 事件触发筛选，支持方向键 / Enter / Esc 和手填；获取不修改当前模型，失败保留上次列表，过期请求不写入已切换设置页。获取与测试均需用户主动触发。分类以紧凑单行列表呈现，共用表头并保留可访问名称；窄屏换行显示字段标签；不再显示无效的日程时间范围控件，旧数字小时字段仅兼容保留，不新增设置字段。迁移仍使用原有确认与结果通知，Key 仍按原有方式明文保存。

### 插件更新

更新设置状态独立保存在内存，重绘不重复发起请求；用户检查公开 GitHub Release，确认后才下载附件。本地比已发布版本新时明确拒绝降级。附件必须来自固定仓库／标签地址，三文件均需完整上传状态、大小限制与 SHA-256；manifest ID／版本与发布一致，最低 Obsidian 版本满足平台公开 API 检查。

仅桌面 `FileSystemAdapter` 分支动态加载 Node 文件系统；不改变插件的移动端声明。安装目录必须匹配当前 Vault 配置目录下的 `plugins/lubi`，拒绝符号链接／特殊目标文件和磁盘／运行版本不一致。旧文件先在 Vault 外的系统临时目录备份并回读校验，暂存目录同时作为跨实例互斥及未完成更新标记。下载、兼容检查和备份全部通过后检查外部修改，再逐文件 rename，manifest 最后；失败仅回滚仍匹配本次内容的目标，不覆盖其他写入，失败恢复信息保留。只触及三份分发文件，配置／日记／任务不参与更新或备份。

不调用内部插件管理器、不执行下载代码、不自动重载。成功后提示已安装磁盘版本、当前运行版本和备份位置，用户重启生效；挂起更新或回滚失败须从备份手动恢复。临时目录备份并非永久归档，断电／进程强杀不保证自动恢复。隔离测试覆盖取消、重复、下载完整性、备份与暂存失败、替换／回滚失败、并发外部修改、残留锁、路径拒绝及生产包设置入口；不以这些测试代替真实 Obsidian 或移动端验收。

## 开发与验证

1. 在独立测试 Vault 或隔离副本操作，用 `npm ci` 按锁文件安装。
2. `npm run build` 执行类型检查与压缩生产构建；`npm test` 运行核心、模拟 UI 和浏览器布局。设置回归使用合成配置与模拟接口，不访问真实服务；浏览器检查包含 AI 收起 / 展开、明暗主题及窄屏，并在插件样式之后叠加原生设置规则，检查标签左对齐、字段填充及说明文字宽度，避免仅在简化主题下通过。
3. 布局验证设置 `LUBI_REQUIRE_BROWSER=1`，必要时设置本机 `LUBI_BROWSER`，禁止将跳过当通过。
4. 构建产物可通过 `LUBI_OUT` 写到测试目录。验证真实生产包时设置 `LUBI_TEST_PLUGIN=../main.js` 后执行 `node test/smoke.mjs`；路径相对 test 文件。
5. 本仓库已有分发目录被 Git 跟踪，应同步 main.js、styles.css、manifest.json 并核对哈希；源码目录生成物不提交。
6. 热重载调试：`npm run dev:vault` 以监听模式构建到本仓库 `.obsidian/plugins/lubi/`，并同步 `styles.css`、`manifest.json` 的修改；该目录的 `.hotreload`（本机空标记文件，已被 .gitignore 忽略，缺失时新建即可）让已启用的 hot-reload 插件在文件变化后自动禁用再启用 Lubi（整体重载，界面内存状态会重置）。开发版未压缩、带内联 sourcemap，且直接读写本 Vault 数据；提交前运行 `npm run build:vault` 覆盖为生产包并核对哈希。
7. 在真实 Obsidian 中重启或禁用再启用插件，人工检查关键路径、空状态、错误输入与移动端。模拟测试不能替代这一步。

已知验证边界：真实 Obsidian、真实在线更新与移动端仍需人工验收。窄屏时间轴刻度列保留完整拖拽读数的宽度；浏览器检查仍强制验证轴侧对齐、主题、边界与响应式。不得将模拟检查通过或浏览器跳过描述为真实客户端验收。

## 发布与隐私

- manifest、package、package-lock 根版本一致；源码 versions.json 映射兼容版本。当前源码版本为 1.7.1；正式发布以 GitHub Release 及其附件为准，代码推送不会自动产生 Release。
- 不提交日记、接口密钥、工作区状态、助手会话、导出与私有备份；只显式暂存确认过的文件，推送前核对远程、分支和暂存差异。
- AI 为可选功能，只在用户动作下请求接口；当前 Key 明文保存在普通设置，curl 兜底跳过证书校验，仍待安全加固。
- 跨午夜重编辑关联和合法 JSON 的结构校验仍有已知限制，见 CHANGELOG；不要把局部保护描述成完整的数据损坏恢复。

### 悬停提示实现

`src/ui/tooltips.ts` 集中管理 Lubi 范围内的简短提示和信息卡片：250ms 悬停延迟、键盘聚焦、窗口边缘避让、单例显示和关闭清理。`tip`、`infoTip`、`hoverTip` 复用这一入口；任务与记录信息卡只显示标题、数据和可选备注，不附加操作页脚；界面中的原生操作提示转为自绘提示，并用隐藏文字与 `aria-labelledby` 保留可访问名称。表单输入与区域名称保留可访问名称，不把这些名称直接当成悬停内容。`quietControls` 集中列出不需提示的控件，`.lubi-quiet-action` 只标记明确批准静默的操作；原生 `title` / `aria-label` 转为隐藏名称和 `aria-labelledby`，不丢失读屏信息。命中静默控件或其子图标时，`targetOf` 不向父级详情卡冒泡；父级自身的详情仍保留。常见编辑 / 删除、切换 / 展开、分类、重复文字等不弹提示，有特殊后果的取消排期、跳过本次和记录确认仍保留。任务 ▶ 与补记在 `normalize` 中采用简短视觉文案，完整可访问名称独立保存。监听与 DOM 观察器在插件卸载时释放，不覆盖 Obsidian 全局提示样式。

### JSON 数据导出

更多菜单与命令面板统一为「导出数据 JSON」。导出 envelope 的 `format` 为 `lubi-data`、`version` 为 1；`taskStore` 保留保存文件中的 schema v14 与未知字段，`records` 为日记中可解析的 Rec（含实际、支出、预计快照和 extra），并附 `exportedAt`。导出等待当前任务写入队列，读取磁盘，不迁移或回写源文件；唯一文件名避免重复导出覆盖，失败提示且不生成不完整文件。多文件读取不是原子事务，应在保存完成后导出。插件设置和凭据不导出。不是完整 Vault 备份或追加任务导入格式，不提供新恢复入口；保留原 `export-csv` 命令 ID 仅为兼容已有快捷键，显示名称与输出均为 JSON。

## 异步工作 MVP（未发布）

Task 保留 v14，新增可选 `executor`（self/background）和 `backgroundRuns`。没有字段的旧任务默认本人，不在读取时迁移或写入真实文件。一次性任务使用 once 键，重复任务以发生日分别保存 ready/running/review/accepted；时间为手动标注的累计毫秒，不是实际机器遥测。

交付进入 review 而非 done；返工进入 ready，不自动重启 Agent。验收只修改状态，不造日记或排期。已完成但未排期的一次性任务以 doneAt 的本地标记完成日只读显示；不会生成甘特日期段。后台信息不进入 Journal 或 metrics；Task.estimate 仍代表本人预计投入。

任务写入复用复制、排队和磁盘比较机制；运行状态修改及验收失败不发布内存状态，普通表单保留最新后台元数据。计划修改与状态互不覆盖。后台 clock 每 30 秒仅改 DOM，面板关闭清理计时器，不推断实际 Agent 已停止。

实际写入默认不完成；明确完成并记录才设置状态／doneDates。completionDate 与实际日记日期分开，避免今天审核昨天的重复项时完成错日期。取消完成保留历史记录；手动补记必须有明确计划并保持待确认。旧自动记账字段留在设置兼容，但不会触发写入或删除。

验收详情及回归说明见 [异步工作 MVP](mcp-lubi-async-workflow.md)。公共 JSON 新增规划格式和已有时间分类不扩展为执行命令入口。
