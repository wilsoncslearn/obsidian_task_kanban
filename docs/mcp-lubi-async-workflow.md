# Lubi 异步工作 MVP

参考日期：2026-10-14。基于 1.7.1 的未发布开发改版；不是正式 Release。

## 范围

第一轮只实现三项：

1. 区分本人实际投入与 Agent 后台手动标注。
2. 增加跨日期的「需我处理」审核队列。
3. 解耦任务完成、真实记录和按计划补记。

不新增时间分类，不做跨电脑自动采集、Agent 调度、积分排行或数据恢复平台；不自动迁移、清空或重新解释真实日记和任务数据。JSON 新增规划格式继续沿用已有类别、日期和整数分钟校验；执行方式由用户在任务界面明确选择。

## 使用流程

### 本人任务

- 保存计划可以不填预计或日期。
- 勾选完成只改变任务状态；取消完成保留真实记录。
- ▶ 打开本人实际字段，默认动作「记录实际（不完成）」；另有明确的「完成并记录」。
- 部分实际记录不计为任务完成，未完成计划仍可见。
- 未排期的一次性任务完成后仍保留空计划日期；仅按本地标记完成日出现在当天清单，不产生甘特日期段。

### Agent 后台任务

- 任务表单「＋ 执行方式」选择「Agent 后台（手动标注）」。旧任务没有字段时默认本人。
- 任务行机器人按钮标记后台运行，收件箱按钮标记结果待审核。这些按钮只保存状态，不启动、停止或访问任何 Agent。
- 「需我处理」跨全部日期显示待审核结果，不受当前日历日期限制。
- 验收完成不写入日记；返工进入待重新启动，不自动开始新一轮计时。
- 本人审核用时通过独立的实际入口记录；后台墙钟时间不进入个人覆盖、重叠、分类或负载统计。预计仍指本人预计投入。
- 后续动作是同项目的独立未安排任务草稿，不生成父任务，不继承预计、日期或后台执行方式；取消不保存。
- 重复任务按发生日分别标注／验收。实际记录日期可晚于被审核的发生日，不误完成其他日期。

### 按计划补记

- 只能由用户明确点击；要求已发生的日期、计划开始时间和正的有效预计值。
- 没有计划时不猜测 09:00 或 30 分钟。
- 新记录保留「按计划」待确认；补记和撤销均不改变任务完成状态。
- 记录已被核对、修改或存在无法区分的相同记录时，撤销保留数据并提醒核对。

## 数据与保护

- 保持 TaskStore v14，新增可选 executor 和 backgroundRuns；不在 load 时写入或迁移。
- 一次性任务使用 once 键，重复任务逐日保存 ready/running/review/accepted。
- 后台累计时间是手动状态之间的墙钟标注，不是精确机器遥测；关闭面板不意味着 Agent 已停止。
- 后台状态、验收和保存采用排队、复制写入及磁盘比较；冲突或失败不发布虚假状态。普通编辑保留最新后台信息和未知字段。
- 旧 promptLogOnComplete 设置保留兼容，但不再触发隐式记账或删除。
- 删除实际记录保留规划任务及完成状态；旧版 record-origin 占位项保持兼容成对删除。删除任务的确认窗口仍允许用户明确选择关联记录的处理方式。
- 原日记、既有预计快照、项目关系、任务 ID、类别和未知字段不进行批量重写。

## 分发决定

起初用户选择独立测试包；随后明确授权覆盖当前安装版，并使用已有 Git 管理代码。当前部署决定以这次授权为准，不再保留旧安装程序。

已将 `插件源码/lubi/preview/mvp-build/` 的已验证生产构建同步到 `.obsidian/plugins/lubi/`：更新 `main.js` 和 `styles.css`；`manifest.json` 原本相同，仅核对而不重复写入。三个程序文件 SHA-256 与已通过完整生产包回归的构建一致，重新从当前源码构建也得到同一组哈希。

当前 Vault 已启用 Hot Reload 0.3.1。该插件只对目标目录中存在 `.git` 或 `.hotreload` 的插件执行重载，因此补入空的 `.obsidian/plugins/lubi/.hotreload` 标记。保持原插件启用配置，不改写 `data.json`、任务数据或日记。Vault 正在 Obsidian 中打开时，文件事件应由现有 Hot Reload 接手；若界面未更新，可运行命令 `Hot Reload: Check plugins for changes and reload them`。

分发程序文件已由 Git 跟踪。覆盖前将旧程序的原始字节保存为 Git blob，保留短期回退手段；没有修改 Git 索引、分支或原有未提交源码，没有自动提交、推送、打标签或发布。未被提交或引用的 Git 对象可能被垃圾回收，该短期回退不替代正式提交记录。新增 `.hotreload` 标记应随程序文件纳入后续明确选择范围的 Git 提交。

此前测试包不包含个人记录或密钥，作为隔离测试产物保留。其源码增量补丁基于开始工作时已有未提交改动的副本，不是干净 HEAD；应用前核对基线。

版本保持 package / lock / manifest 一致的 1.7.1 开发基线，未创建正式发布或标签。安装文件同步与热重载条件已核对，但 MCP 未观察真实 Obsidian 客户端的加载结果；不能将文件校验或模拟回归当作真实 Obsidian／移动端验收。

## 人工验收清单

- 同时标注多个后台任务，确认个人实际时间不增加。
- 在另一个日期查看仍能看到待审核结果。
- 记录五分钟审核耗时但不验收，确认结果仍在队列。
- 返工不自动重启 Agent；再标注运行与交付后可验收。
- 取消完成保留已有真实记录；补记撤销不取消完成。
- 今天审核昨天的重复结果，只完成昨天那一次。
- 不填预计、计划日期也能完整走完后台流程。
- 窄屏、键盘、默认主题和自定义主题检查控件可达与阅读体验。

## 剩余边界

- 本轮没有解决历史 AI Key 明文设置、桌面 curl 兜底 TLS 校验问题，不能宣称云端生产安全。
- 未增加跨设备自动状态同步、累积任务偏差、完整备份恢复或项目分析平台。
- 不自动发布、推送、创建标签或改变个人配置；正式发布与真实客户端验收需单独确认。
