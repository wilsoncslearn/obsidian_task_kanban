### 本次补查新确认的问题

1. **一键更新和 README 链接指向的仓库，匿名访问不到。**
   - `src/core/pluginUpdate.ts`，以及 README 里的克隆和 Releases 链接，都指向 `HP-Patience/obsidian_task_kanban`，也就是现在的 `previous-origin`。当前的 `origin` 是 `wilsoncslearn/obsidian_task_kanban`。
   - 两个仓库的 API 和网页匿名访问都返回 404，推断是私有仓库。
   - 代码把 404 当成“还没有发布”，所以“检查更新”永远显示“暂无正式发布版本”，用户看不出其实是访问不到。
   - README 写的“访问公开 GitHub API”也和现状不符。
2. **CHANGELOG 和代码对不上。** 1.8.0 第一条写着：日历日视图的时间轴按可用高度压缩小时刻度，00:00–24:00 一屏显示、不再滚动。但当前代码每小时固定 56 px（`calendarDay.ts` 第 87 行）。今天按你的选择，时间轴已恢复为“面板内固定高度、内部滚动”。
3. **`插件源码/lubi/.codegraph/` 没被忽略**。它和 37 个日志、`scripts/__pycache__/`、`test/product-plugin.cjs` 一起出现在未跟踪列表里。
4. **`npm audit` 报的 3 个中危只影响开发阶段。**
   - esbuild 0.24 的开发服务器漏洞：本项目不用 serve 功能。
   - `obsidian` 类型包依赖的 moment。
   - 升级到 esbuild 0.28.2 和 obsidian 1.14.4 后可以清零。
5. **官方 lint 插件有 peer 依赖冲突。** `eslint-plugin-obsidianmd` 0.4.2 要求 `obsidian` 精确为 1.8.7，和本项目的 1.13.x 冲突，安装时需要配 `overrides`。
6. **隐私方面，已跟踪的内容没发现问题。**
   - 文本文件里没有本机路径。
   - HEAD 里的任务数据是 35 字节的空模板。
   - 12 张手册截图都有文档引用。

### A2 删除临时日志（可选）【删除】

- 删除 `插件源码/lubi/test/` 下的 37 个 `.log`，以及 `插件源码/lubi/scripts/__pycache__/`。
- 这些都是以前测试运行留下的输出，没有被 git 跟踪，删了无法恢复。做完 A1 后它们已经不再显示，不删也行。

### A3 个人文件停止跟踪【git】

- 执行 `git rm --cached -- 任务/任务数据.json .obsidian/workspace.json .snapshots/config.json`。磁盘上的文件保持不变。
- 理由：
  - HEAD 里的任务数据是空模板，工作区里却是真实任务，一旦误提交就会带出去。
  - 另外两个文件已经写在忽略规则里，但仍被跟踪，Obsidian 和工具会不停改写它们。
- 任务文件不存在时插件会自动创建（见 `src/core/tasks.ts` 的写入逻辑），所以克隆后不需要模板。
- 同时修改 AGENTS.md 第 21 行里“空的模板任务数据”的说法。
- 历史提交里仍保留这些文件的旧版本。仓库保持私有就没有影响；以后要公开，见 D1。

### A4 清理旧 Key【删除】

1. 请你在 Obsidian 里打开 Lubi 设置，随便改一项再改回来，触发一次保存，`data.json` 里的旧 Key 就会被清空。我会用只输出“空”或“非空”的命令核对，不打印内容。

### A6 1.8 分 4 次提交【git】

提交前先做这几步：

1. 停掉后台的 dev:vault 监听进程。
2. 运行 `npm run build:vault`，核对三个分发文件和生产构建的哈希一致，并确认 `main.js` 不带 sourcemap。
3. `LUBI_REQUIRE_BROWSER=1 npm test` 全量通过；再用 `LUBI_TEST_PLUGIN` 指向分发包，跑一次冒烟测试。
4. 每次提交前运行 `git diff --cached --check`，并扫描暂存内容里有没有密钥；逐张查看截图，确认都是合成数据。

| 次序 | 提交信息 | 内容 |
| --- | --- | --- |
| 1 | `chore(repo): ignore dev artifacts and untrack personal files` | 两个 `.gitignore`，以及 A3 停止跟踪的文件 |
| 2 | `feat(lubi): 1.8.0 work review, light task form, async workflow and MONO tokens` | `src/`（21 个修改、7 个新增）、`styles.css`、`test/`（16 个修改、13 个新增）、`esbuild.config.mjs`、`package.json`、`package-lock.json`、`manifest.json`、`versions.json`、`scripts/screenshots.py` |
| 3 | `docs(lubi): guides, screenshots and plans for 1.8.0` | README、教学手册、CHANGELOG、AGENTS.md；`docs/`（2 个修改、6 个新增，含本文）；`docs/images/`（4 个修改、1 个新增）；`附件/lubi手册/` 的 3 张截图 |

- 第 2 次提交不再按功能拆分，因为 `styles.css`、`modals.ts` 等文件里几个功能的改动交织在一起。按功能拆要逐段暂存，费时也容易拆错。如果你希望拆，我先出一份逐段方案给你审批。
- 提交后要继续开发，再启动 dev:vault。它会把分发文件改回开发版，下次提交前重复第 2 步；B6 会自动做这项检查。

## 4. B：工程化（1.8.x）

### B1 测试改用 `node --test`【git】

- 目录分为 `test/core/`、`test/smoke/`、`test/layout/`、`test/helpers/`。生成物和日志统一输出到被忽略的 `test/.out/`。
- 两个公共辅助文件：
  - `helpers/browser.mjs`：统一查找 Chrome 或 Edge，覆盖 Windows 和 Linux 路径，并支持 `LUBI_BROWSER` 环境变量。用它替换 11 个布局测试里各自写死的路径。
  - `helpers/page.mjs`：生成测试页时固定写入 `<meta charset="utf-8">`。
- 脚本：先构建测试包，再分别运行 `node --test "test/core/*.mjs"`、`node --test "test/smoke/*.mjs"` 和 `node --test --test-concurrency=1 "test/layout/*.mjs"`。一次运行会报告全部失败并给出汇总，新增测试也不用再改 `package.json`。
- 验证：迁移前后的测试数和通过数一致，都是 33 个。

### B2 最小 CI【远程】

- 新增 `.github/workflows/ci.yml`。推送到 main 或提 PR 时，在 ubuntu 上用 Node 24，在 `插件源码/lubi` 目录依次运行 `npm ci`、`npm run build`、`test:core`、`test:smoke`。
- 布局测试暂不进 CI，因为它依赖浏览器和字体。先在 Windows runner 上以不阻断的方式试跑两周，再决定是否纳入。
- 私有仓库的 Actions 免费分钟数有限，Windows 按 2 倍计算；core 和 smoke 每次只需几分钟。

### B3 接入官方 lint【依赖】

- 新增 `eslint` 9、`typescript-eslint` 8 和 `eslint-plugin-obsidianmd` 0.4.2。在 `package.json` 里加 `overrides` 解决前面提到的 peer 冲突；`eslint.config.mjs` 使用官方推荐规则。
- 先用 eslint 9：这个插件的 peer 依赖要求 `@eslint/js` 9，和 eslint 10 搭配没经过验证。
- 先只报告、不阻断：我按规则把问题汇总给你，再分批修复，清零后再接入 CI。

### B4 依赖与版本声明【依赖】

- `obsidian`：从 `latest` 改为固定的 `1.14.4`，同时消除 moment 告警。
- `esbuild`：从 `0.24.0` 升到 `0.28.2`，升级后比较构建产物并跑全量测试。
- `package.json` 增加 `"engines": { "node": ">=22" }`，`@types/node` 对齐 Node 24。
- `tsconfig.json` 的 `moduleResolution` 改为 `bundler`。
- TypeScript 暂时留在 5.9。7.0 已经发布，但还没确认 lint 工具链支持它。
- 根据 D3，把 `minAppVersion` 设为实际验证过的版本，并同步 `versions.json`。
